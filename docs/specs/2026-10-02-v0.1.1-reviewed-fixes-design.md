## Aborted/error exchange behavior

Pi intentionally ends assistant messages with `stopReason: "aborted"` or `"error"` before their streamed tool calls execute.
Such messages can have no tool results. Later user input must not turn this valid lifecycle event into a paging error.

Raw history and provider selection have distinct responsibilities:

- Raw history retains the failed assistant and every actual contiguous result.
- History retains the original assistant and result object identities.
- Provider selection validates actual results. Then it omits the failed exchange.
- Provider replay excludes the failed assistant and its contiguous owned results.
- No layer invents tool results or rewrites saved messages.
- Both layers use the reviewed failed-turn policy.

Retain support for zero, partial, and complete result sets on failed turns.
Retain strict validation for normal incomplete exchanges and for duplicate, mismatched, or orphan results.
Do not let omission hide malformed results.
Keep the latest valid-result protection. Interrupted exchanges must not receive that protection.
