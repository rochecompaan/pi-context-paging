## Precedence inspection and one-variable experiment

The required local CLI/package inspection did not start the global Pi executable. `node_modules/.bin/pi` is a Node wrapper that loads `./cli-runtime.js`. `dist/config.js` defines package-directory resolution as:

```js
function getPackageDir() {
  const envDir = process.env.PI_PACKAGE_DIR;
  return envDir ? normalizePath(envDir) : isBunBinary ? dirname(process.execPath) : findNodePackageDir(__dirname);
}
```

`getThemesDir()` calls `getPackageDir()` before forming the `dist/modes/interactive/theme` path. Therefore `PI_PACKAGE_DIR` takes precedence over the npm package resource path.

The smallest one-variable experiment was run exactly as follows:

```sh
set -euo pipefail
cd "$PAGING_REPO"
env -u PI_PACKAGE_DIR npm run check:package 2>&1 | tee /tmp/pi-context-paging-check-package-without-pi-package-dir.log
```

It exited zero and printed:

```text
verified rochecompaan-pi-context-paging-0.1.0.tgz and 4 history tools
```

Conclusion: the inherited `PI_PACKAGE_DIR` overrides the locally installed Pi package directory, points at a Nix resource tree without `dark.json`, and causes the pre-probe failure. Unsetting only that variable makes local Pi resolve its own packaged theme resource and pass the real-Pi smoke test.
