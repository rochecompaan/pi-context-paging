## Review Focus

Each risk has an explicit behavioral check in its owning task. Existing reviewed cases supply these checks without duplicate tests.

1. Malformed or cached usage: Pi's `totalTokens` choice controls anchor validity, not a different local rule. Task 1 retains the malformed-usage and cached-response cases.
2. Persistent system/tool updates absent from outgoing messages: calibration subtracts the full persistent suffix and counts resident changes once. Task 1 retains both outgoing shapes.
3. Lifecycle changes and projection failures: stale anchors and transient-message provenance must not survive them. Task 1 retains reset and recovery cases.
4. Failed turns with malformed actual results: omission must not hide duplicate, mismatched, or orphan results. Task 2 retains strict validation cases.
5. Failed turns before a persistent request and transient instruction: removal must preserve provenance alignment and incoming calibration. Task 2 retains both regression cases.
